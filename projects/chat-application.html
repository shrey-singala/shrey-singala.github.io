Multi-Threaded Chat Application

A terminal chat client (and companion server) written in C that talks over a custom binary protocol on TCP. It's full-duplex (you can watch live messages arrive while you're mid-sentence) and it's engineered so that bad input never gets you kicked off the server.

  • C
  • TCP / IPv4
  • POSIX Sockets
  • pthreads
  • Binary Protocol
  • Signals
  • DNS Resolution

01 Overview

The client connects to a chat server, logs in with the system username, and then does two things at once: it streams incoming messages to the screen and it sends whatever you type. Doing both simultaneously, cleanly, without one blocking the other, is the heart of the project.

Everything travels as fixed-size binary frames rather than plain text, so I had to design the wire format, handle byte ordering across the network, and validate every field on both ends.

02 How I built it

  1. Custom binary protocol

    Messages are fixed 1,064-byte frames: a 4-byte type, a 4-byte UNIX timestamp, a 32-byte username, and a 1,024-byte payload. I mapped this onto a packed struct and send/receive it in struct-sized chunks, converting multi-byte fields to network byte order (htonl/ntohl). Six message types cover login, logout, sending, receiving, disconnects, and system notices.

  2. Concurrent send & receive

    A dedicated pthreads receive thread continuously reads, parses, and prints server messages, while the main thread handles user input from STDIN. That split is what makes the client feel live instead of taking turns.

  3. Never get disconnected

    The server disconnects clients that send malformed or too-frequent messages, so I validate every outbound message (non-empty, printable ASCII, length limits, newline stripping) before it goes out, and enforce rate limits via careful synchronization of shared state across the two threads. Bad input is reported to the user instead of ever reaching the server.

  4. Polish & clean shutdown

    The client resolves --domain names via DNS, highlights @mentions in color with a terminal bell, and shuts down gracefully on Ctrl-C, SIGTERM, or EOF: sending a logout, closing the socket, joining the thread, and freeing memory.

03 What I learned

  • BSD socket programming and the TCP connection lifecycle
  • Designing a binary wire protocol and handling network byte order
  • POSIX threads and safely sharing state between them
  • Signal handling and leak-free resource cleanup in C
  • Defensive programming: validating input so failures never reach the server
