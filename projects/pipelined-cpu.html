2-Way Superscalar Pipelined CPU

Starting from a provided single-cycle MIPS processor, I rebuilt it as a 5-stage pipelined CPU in Verilog, adding new instructions and full hazard detection with stall logic, then verified it cycle-accurately on an FPGA.

  • Verilog
  • MIPS
  • 5-Stage Pipeline
  • Hazard Detection
  • FPGA
  • Xilinx Zynq-7000
  • AMD Vivado

01 Overview

The starting point was a single-cycle MIPS CPU that could only run ADD, ADDI, LW, and SW. The goal was to turn it into a 5-stage pipeline (Instruction Fetch, Decode, Execute, Memory, and Write-Back) that runs a wider instruction set and correctly handles the data hazards that pipelining introduces.

Pipelining overlaps instructions to raise throughput, but it creates a new problem: an instruction can need a result that an earlier instruction hasn't written back yet. Solving that cleanly was the most interesting part.

02 How I built it

  1. Extend the instruction set first

    Before pipelining, I added three R-type instructions (SLL, XOR, and NOR) to the single-cycle design by extending the ALU and control unit. Doing this first meant any instruction bugs were isolated from pipeline bugs later.

  2. Build the 5-stage pipeline

    I inserted pipeline registers between the stages to hold each instruction's state as it advances, and rewired the datapath across modules so the five stages run concurrently on different instructions.

  3. Hazard detection & stalls

    I built a dedicated hazard-detection module (kept separate from the top-level design for clarity) that spots data hazards and inserts stalls until the needed data is available. This included adding an enable input to the program counter so the pipeline can be frozen when a stall is required.

  4. Verify on FPGA

    I validated the design with AMD Vivado behavioral simulation targeting a Xilinx Zynq-7000 (xc7z020clg484-1). The testbench confirmed correct, cycle-accurate results: for example sll, xor, and nor producing exactly the expected register values.

03 What I learned

  • How instruction pipelining works stage by stage, and why it speeds things up
  • Data hazards and the stall / detection logic that resolves them
  • Writing modular Verilog RTL and wiring it through a top-level design
  • Extending an ALU and control unit to support new instructions
  • FPGA verification and reading Vivado waveforms to debug cycle-accurate behavior
